Disk Growth Monitor 2.4.1 - Parquet + DuckDB - Windows x64

Private Python/Qt runtime is bundled under .venv.
New snapshots use checksummed ZSTD Parquet metadata; file contents are never backed up.
Comparisons use private DuckDB RAM sessions with bounded spill, removed when closed.
Temporary exports are limited per active scan and cleaned after successful Parquet publication.
A complete interrupted export may be kept as one verified gzip checkpoint, read without expansion.
Existing checkpoints are preserved by default; incomplete exports restart. Legacy retained CSVs are not auto-deleted.
Disk allocation is preferred. If a capture has no per-file allocation, the view automatically uses logical size with an explicit notice.
Logical path size is not Windows Used and can exceed volume capacity due to hardlinks.
Unknown measurements are retained under size filters, never silently treated as zero.
The first capture shows New sizes; Old and deltas are unavailable until a previous capture exists.
Manual and scheduled scans use saved profiles; the GUI asks before using unsaved changes.
The completed scan, history, CLI output and log identify the profile that actually ran.
Scan profile choice is remembered; comparison milestones follow capture times independently.
Startup checks for a newer official release by default, with an opt-out in System / Update.
This check only notifies; installation still requires the user's explicit action.
Task highest privileges and the profile's MFT switch are separate settings.
GUI startup loads saved milestones/summaries only, not full history or a comparison.
Legacy JSONL history is imported explicitly once from History; source logs are retained.
Older SQLite can be converted to JSONL with the compatibility tool, then imported.
No automatic deletion/conversion of legacy history on startup. Interrupted/failed imports preserve the source.
One comparison table and whole-branch tree include records captured at either milestone.
The recorded delta, verified additions/deletions and Windows Used are separate measurements.
Short column labels have tooltips. Filters and paging do not change the pair totals.
The detail header shows both snapshot IDs, capture times and measured totals.
The Summary tab ranks up to 10 folders each for growth, shrinkage, additions and
missing records, across the entire pair. It loads on demand from the open session.
The GUI shows GB/MB and one signed change value; calculations still use raw bytes.
App Move previews and relocates selected private data or confirmed portable
folders between local NTFS volumes. It verifies copies before making junctions,
keeps the old data, and requires separate approval for old-copy cleanup.
It does not move registered Windows/Store packages or modify their registrations.
Double-click discovered folders to open them; the context menu can show their
location in Explorer, show properties, or copy the source/destination path.
Snapshot details, diagnostic reports, cleanup results and move history use tables.
AI prompts are previewed and copied explicitly, with no automatic submission.
The footer has a Show/Hide timing/result report and separates collection, import/save, comparison and table loading.
No global Python, pip, System PATH, Task Scheduler job or Windows Service is installed.
Choose an empty folder, preferably on D: to avoid consuming C: space.
The editable source folder must not be overwritten by this installer.

GUI: DiskGrowthMonitor.exe
CLI: dgm.exe --help
The GUI requests Windows UAC administrator approval at every unelevated launch.
This installer also requires UAC administrator approval.
Headless CLI/background jobs retain explicit per-operation privilege checks.

WizTree is proprietary and NOT included. Select your installed WizTree executable
in the System tab. WinDirStat/gdu can be downloaded explicitly into .venv/tools.
No scan, cleanup or automatic task starts during installation.
Cleanup proposals contain compressed metadata, expire after one hour, and start
with no items selected. Tool actions may affect an entire cache as clearly shown.
Review the exact selection across pages before confirming. Results distinguish
deleted file sizes, measured changes in free space, and skipped items.
Folder inspection is opt-in, read-only, bounded, and never defaults to a drive.

Upgrades preserve data and logs. Close the application before upgrading.
For app-assisted updates, the app downloads the official Release, checks SHA-256,
backs up config/history and temporarily disables/stops only its own runner.
The runner registration is retained and its original state is restored afterward.
One Update button runs the full download/install workflow. An observer started
before elevation reopens the app in the original user session after verification.
Manual upgrades require a disabled/stopped runner; legacy builds may need it removed.
Updates started from source use a managed .dgm-app runtime inside the current app
folder and keep the existing data/log home. The same launcher opens the new app.
Source code and its development .venv are retained.
Before uninstalling, stop scans and remove any Task/Service using the application.
Uninstall preserves scan history, logs and tools downloaded after installation.
Review retained files yourself; the uninstaller does not erase the whole folder.

This build is not code-signed. Windows may show an unknown-publisher/SmartScreen warning.
Only run installers from the official project Release. Compare SHA256SUMS.txt.

Portable mode: installer.exe /PORTABLE=1
This skips Start menu/Desktop shortcuts and the Add/Remove Programs entry.
It still includes an uninstaller, which preserves user-created data and logs.
